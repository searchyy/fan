# 记忆衰减管理系统

基于艾宾浩斯遗忘曲线，用引用频率替代时间戳来管理记忆生命周期。

## 核心概念

每条记忆格式：
```
💡 [P1][2026-01-15][ref:2026-02-10] 用户对虾过敏
```

- 优先级标签（P0/P1/P2）
- 写入日期
- ref：最后一次被实际引用的日期

## 优先级分层

| 级别 | 淘汰规则 | 适用场景 |
|------|----------|----------|
| P0 | 永不自动淘汰 | 核心身份、安全规则、系统配置 |
| P1 | ref 超过 90 天淘汰 | 用户偏好、长期习惯、重要信息 |
| P2 | ref 超过 30 天淘汰 | 临时信息、短期上下文、一次性指令 |

## 工作流程

### 1. 写入记忆

新记忆写入时，添加优先级、写入日期和初始 ref：

```
💡 [P1][2026-02-15][ref:2026-02-15] 老板投资风格：长期持有 2-3 年
💡 [P0][2026-02-07][ref:2026-02-07] 绝不接收/存储密码或私钥
💡 [P2][2026-02-15][ref:2026-02-15] 今天天气不错，老板心情好
```

### 2. 更新引用（ref）

当记忆被实际使用时（影响了输出），更新 ref 为当天日期：

**什么算"被引用"：**
- 在回复中明确提到了该记忆内容
- 通过 memory_search 召回并用于回答
- 行为明显受该记忆影响

**不算引用：** 批量加载记忆到上下文但未实际使用。

### 3. 定期清理

运行 `scripts/memory-decay.sh` 执行清理：
- 扫描所有带标记的记忆条目
- 跳过 P0
- P1：ref 超过 90 天 → 移入归档
- P2：ref 超过 30 天 → 移入归档

### 4. 向后兼容

没有 ref 标记的旧记忆：用写入日期作为 ref。下次被引用时自动获得新 ref。

## 使用指南

### 在 heartbeat 中执行清理

在 HEARTBEAT.md 中添加定期清理任务（建议每周一次）：

```
## 记忆衰减清理 (每周)
运行: bash /path/to/skills/memory-decay/scripts/memory-decay.sh
```

### 手动迁移现有记忆

对 MEMORY.md 中的现有条目，逐条添加标记：
1. 判断优先级（P0/P1/P2）
2. 保留原写入日期
3. ref 设为今天（如果最近用过）或写入日期（如果不确定）
