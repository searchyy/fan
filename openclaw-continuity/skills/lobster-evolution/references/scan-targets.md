## What to look for

- repeated manual steps that should become scripts
- repeated explanations that should become skill instructions
- recurring breakages that need hardening
- user preferences that keep affecting execution
- useful local facts that reduce future discovery cost
- reusable project-analysis patterns that can be standardized into a protocol

## Preferred triad for project analysis extraction

When studying a new project, prefer triangulating from:
- official frontend behavior
- official repo / plugin / docs
- public API behavior

Only add community chatter or secondary sources after the primary triad is clear.

## Promotion heuristic

If the learning changes future behavior more than once, promote it.
If it only matters for today, keep it in daily memory.
