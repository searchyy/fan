# 加密项目深度调查分析

## 分析流程

收到项目分析请求后，按以下顺序执行完整调查，最终输出一份结构化报告。

### Phase 1: 信息收集

1. 确定项目入口（合约地址、Twitter、官网，至少一个）
2. 收集以下原始数据：
   - 合约地址 → 链上数据（区块浏览器）
   - Twitter/X → 社交数据
   - 官网/白皮书 → 项目文档
   - DEX → 市场数据（价格、流动性、交易量）
   - 持仓分布 → 链上地址分析

### Phase 2: 八维分析

按以下 8 个维度逐一分析，每个维度独立评分（1-10）。

#### 维度 1: 项目基本信息
收集并整理：
- 代币名称/符号/区块链/合约地址
- 合约框架（ERC20/DERC20/自定义等）
- 合约状态（是否验证、是否审计）
- 代币总量/部署时间
- 官网/白皮书/Twitter
- 开发者信息
- 竞争项目

#### 维度 2: 核心机制
分析项目的核心玩法：
- 代币的实际用途是什么？
- 经济模型如何运作？
- 是否有创新性？还是纯 meme？
- 积分/奖励/挖矿机制（如有）
- 实时运营数据（活跃用户、TVL、epoch 等）

#### 维度 3: 合约安全分析（关键）
深入审查合约代码和权限：
- 合约框架确认（标准框架 vs 自写）
- 关键机制解读（表格形式）：
  - 合约所有者 → 是否为 EOA/多签/智能钱包
  - 增发上限 → 年化增发率
  - 预铸（Premint）→ 数量和分配
  - pool 变量 → 实际含义（是否为黑洞地址）
  - 锁池状态 → isPoolUnlocked
- 所有者剩余权限（表格）：
  - 每个函数 → 风险等级（低/中/高/已失效）→ 说明
- 特别关注：
  - 是否能 rug pull？
  - 流动性是否可被抽走？
  - 是否有隐藏的 mint 权限？

#### 维度 4: 持仓分布（健康信号）
链上数据分析：
- 独立交易地址数
- 最大持仓方占比
- 前 20 名合计占比
- Top 5 持仓地址列表（地址 + 比例）
- Uniswap/DEX 池占比
- 判断：是否有巨鲸控盘迹象？

#### 维度 5: 预铸归属（潜在卖压）
检查 vesting/unlock 情况：
- 有归属期的地址数量
- 总锁定量占比
- 各地址配对 ETH 量 → 推测身份
- 释放时间表
- 潜在卖压估算（金额）

#### 维度 6: 市场数据快照

#### 维度 7: 团队与社交
开发者画像（表格）：
- 账号年龄/粉丝/技术能力/透明度/此前项目/启动动机/身份核实

竞争对手对比（如有）：
- 创始人/账号年龄/粉丝数/参与率/合约/网站

### Phase 3: 最终裁决

输出格式：

```
最终裁决

评级：[SAFE / CAUTION / DANGER / SCAM]

[一段话总结核心判断]

[如果是早期项目，说明投机性质]

最大的 N 个问题：
1. ...
2. ...

对矿工/参与者而言：[建议]
对交易者而言：[建议]

关键观察节点：[时间 + 事件 + 意义]
```

## 评级标准

- **SAFE (7-10分)**: 合约安全、团队透明、流动性充足、社区活跃
- **CAUTION (5-7分)**: 有创新但存在未验证风险、早期项目、需观望
- **DANGER (3-5分)**: 多个红旗信号、高度投机、可能亏损
- **SCAM (<3分)**: 明确骗局特征、蜜罐、貔貅盘、假项目

## 数据源

按优先级使用：
1. 区块浏览器（Etherscan/Basescan/BSCScan）→ 合约代码、持仓、交易
2. DEX Screener / DexTools → 价格、流动性、交易量
3. Twitter/X API → 社交数据、开发者背景
4. 官网/白皮书 → 项目文档
5. CoinGecko/CMC → 是否收录
6. GitHub → 代码活跃度（如有）

## 输出规范

- 所有数据用表格呈现，清晰对比
- 关键发现加粗标注
- 风险信号用红色标记（文字描述中用 ⚠️）
- 利好信号用绿色标记（文字描述中用 ✅）
- 每个维度给出独立判断，不含糊
- 最终裁决必须明确，不骑墙

## 常见红旗信号速查

- 合约未验证/未审计
- 所有者可无限 mint
- 流动性未锁定
- 单地址持仓 >10%
- Twitter 当天创建
- 无 Discord/TG 社区
- 交易税 >10%
- 买卖不对称（貔貅盘）
- 蜜罐检测失败
- 团队匿名且无历史
- 白皮书抄袭
- 中文内容 + AI 身份伪装
